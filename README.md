# Лабораторная работа № 6

## Вариант

**Вариант 15 — анализ логических дисков.**

## Назначение программы

`LR6_system.exe` перечисляет логические диски, доступные текущему пользователю, и собирает по каждому диску:

- корневой путь;
- тип диска (фиксированный, съёмный, сетевой, CD-ROM и т. д.);
- файловую систему и метку тома;
- общий и свободный объём;
- процент занятого пространства;
- признак успешности получения данных и код ошибки Win32.

Сведения сохраняются в CSV-файл в кодировке UTF-8 с BOM. Для каждого запуска также записывается строка журнала в `lab06.log`, а длительность операции выводится в консоль.

## Используемые Windows API

- `GetLogicalDriveStringsW` — получение списка логических дисков;
- `GetDriveTypeW` — определение типа диска;
- `GetVolumeInformationW` — получение файловой системы и метки тома;
- `GetDiskFreeSpaceExW` — получение общего и свободного объёма;
- `GetLastError` — получение кода ошибки Win32;
- `FormatMessageW` и `LocalFree` — преобразование кода ошибки в текст;
- `WideCharToMultiByte` — преобразование строк из UTF-16 в UTF-8;
- `QueryPerformanceFrequency` и `QueryPerformanceCounter` — измерение времени выполнения.

## Требования к среде разработки

- Windows 10 или более поздняя версия Windows;
- Microsoft Visual Studio Community 2026 или совместимая версия с поддержкой C++;
- компонент **Разработка классических приложений на C++**;
- Windows 10 SDK;
- компилятор MSVC с поддержкой стандарта C++20;
- для экспериментов — Python 3.10 или новее со стандартными модулями Python.

Проекты настроены на Windows SDK 10.0, стандарт C++20 и инструментальный набор MSVC `v145`. В решении есть конфигурации `Debug` и `Release` для платформ `Win32` и `x64`.

## Порядок сборки

1. Открыть `LR6_system.slnx` в Visual Studio.
2. Выбрать конфигурацию `Release` и платформу `x64` (для отладки можно использовать `Debug | x64`).
3. Выполнить **Сборка → Собрать решение**.
4. После успешной сборки исполняемый файл будет находиться в `system\x64\Release\LR6_system.exe`.
5. При необходимости собрать проект `Tests`. Он проверяет экспорт CSV, обработку ошибок CLI, расчёт процента заполнения и экранирование CSV.

Из командной строки разработчика Visual Studio эквивалентная команда имеет вид:

```powershell
msbuild LR6_system.slnx /p:Configuration=Release /p:Platform=x64
```

## Параметры запуска

```text
LR6_system.exe --csv <path> [--runs N]
```

Параметры:

- `--csv <path>` — обязательный путь к выходному CSV-файлу;
- `--runs N` — количество повторов измерения, `N >= 1`; по умолчанию выполняется один запуск;
- `--help` — вывести справку по использованию.

Примеры:

```powershell
.\system\x64\Release\LR6_system.exe --csv .\data\disks.csv
.\system\x64\Release\LR6_system.exe --csv .\data\disks.csv --runs 3
```

При ошибке параметров программа возвращает ненулевой код завершения и выводит справку. При ошибке записи CSV выводятся код и описание ошибки Win32.

## Порядок воспроизведения экспериментов

### Ручной запуск

1. Собрать конфигурацию `Release | x64`.
2. Создать каталог `data`, если его нет.
3. Запустить программу, например:

   ```powershell
   .\system\x64\Release\LR6_system.exe --csv .\data\disks_manual.csv --runs 3
   ```

4. Сравнить значения длительности в консоли и данные дисков в CSV-файле.
5. Проверить `lab06.log`, содержащий результат каждой операции.

### Автоматический сценарий

Сценарий `scripts\run_experiments.py` выполняет серии по три запуска для состояний `baseline`, `10`, `50` и `100`. Перед измерением он создаёт в `data` временный файл размером 10, 50 или 100 МБ, запускает программу, читает CSV, затем удаляет временный файл. Итоговые данные записываются в `data\results.csv`.

Запуск из корня репозитория:

```powershell
python .\scripts\run_experiments.py
```

Сценарий ожидает исполняемый файл по пути `system\x64\Release\LR6_system.exe`. Перед запуском необходимо собрать эту конфигурацию и убедиться, что на диске достаточно свободного места для временных файлов.

## Ограничения доступа и безопасности

- Программа не изменяет содержимое дисков и не требует прав администратора для обычных доступных томов: выполняются только чтение метаданных и информации о свободном месте.
- Результаты записываются с правами текущего пользователя. Каталог для CSV и журнал должны быть доступны для записи; существующий CSV может быть перезаписан.
- Для защищённых, отключённых, недоступных или сетевых дисков отдельные вызовы Windows API могут завершиться ошибкой. Такие ошибки сохраняются в CSV, а недоступные значения не следует считать корректными.
- Не рекомендуется указывать системные и защищённые каталоги в качестве места сохранения CSV или журнала.
- Экспериментальный скрипт создаёт временные файлы в `data` и удаляет их после серии. При прерывании скрипта оставшийся файл нужно удалить вручную.
- Не запускайте программу с правами администратора без необходимости и не передавайте ей пути из недоверенных источников.

## Структура репозитория

- `src/` — исходный код программы;
- `Tests/` — проект и исходный код проверок;
- `system/` — проект основного приложения и результаты сборки;
- `scripts/` — сценарии экспериментов;
- `data/` — CSV-результаты и временные файлы экспериментов;
- `diagrams/` — диаграммы;
- `report/` — материалы отчёта.
